# Techstra 视频研究与首轮实验

日期：2026-10-29。代码分支：`model/video-behavior-research`。

## 1. 本轮结论

已经完成公开数据获取、校验、特征提取、分类器训练、按参与者划分的评估、阈值实验，以及完整视频到事件时间线的运行。当前最有用的成果是**可复核的视频行为事件**：持续转头、目光方向变化、未检测到人脸、多张人脸。

本轮最重要的发现是：**明显转头容易识别，头不动时的细微眼动更难**。把两者混在一起评估，会让目光模型显得更好。专门的目光模型改善了眼动识别；更大的数据集和训练折内的阈值选择进一步降低了误报。

| 实验 | 数据与拆分 | 实测结果 |
|---|---|---|
| 头部偏转 | 3 人公开场景数据；每次留一人测试；657 个可测帧 | AUROC **0.9998**；固定阈值下 FPR 0/192，召回 459/465；覆盖全部选中帧的 85.3% |
| 头正向时的眼动：关键点基线 | 同一 3 人数据，154 个可用帧；留一人测试 | AUROC **0.4781**（HGB） |
| 头正向时的眼动：MobileGaze | 上述同一 154 帧与相同参与者划分 | AUROC **0.7786**；FPR 30.1%，召回 69.1%（LR、阈值 0.5） |
| 更大规模眼动实验 | Columbia，56 人、1,176 帧；5 折按人划分；嵌套选择阈值 | AUROC **0.8414**；FPR **7.74%**；召回 **60.12%**；平衡准确率 **76.19%** |
| 外部数据迁移 | 3 人数据训练的 MobileGaze/LR 直接测试 Columbia，无 Columbia 训练 | AUROC **0.7542**；FPR 12.5%，召回 42.2% |

这些任务的标签是方向或场景标签。它们尚未提供真实面试中“使用了 AI”的检出率。0.9998 描述的是预设的明显头部方向差异，不是作弊识别准确率。

## 2. 已有研究怎么做

**Duolingo，2024。** 使用逐帧目光方向、散点图和视频时间线帮助人工寻找相关片段。论文也指出，思考时自然看向别处会增加判断的不一致性。这与 Techstra 的“提示面试官复核”方向最接近。[论文](https://arxiv.org/abs/2409.16923)

**Cheating Detection Pipeline，2021。** 视频流水线检测额外人员、电子设备和候选人离开画面，组合人脸检测、跟踪和物体检测。论文评估使用私有视频数据，不能直接作为我们的开放训练集。[论文](https://arxiv.org/abs/2106.14483)

**AI-assisted AVI 研究。** 245 名参与者被分配到无 ChatGPT、逐字朗读、个性化回答条件。公开 OSF 文件列表目前有统计数据 `.sav` 和补充材料 PDF；未列出原始视频。可以借鉴实验设计，无法从这两个公开文件训练像素级视频模型。[原文](https://onlinelibrary.wiley.com/doi/10.1111/ijsa.12491)、[OSF](https://osf.io/uzg9d/)、[本次核对的文件 API](https://api.osf.io/v2/nodes/uzg9d/files/osfstorage/)

**组件工具。** MediaPipe 提供人脸关键点、变换矩阵和视频/流式模式；OpenFace 提供头姿和目光分析；L2CS-Net 是专用目光估计方法。MobileGaze 提供基于 Gaze360 的轻量 ONNX 权重。本次实际运行了 MediaPipe 和 MobileGaze，没有运行或宣称比较过 OpenFace/L2CS 的完整推理模型。[MediaPipe](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/python)、[OpenFace](https://github.com/TadasBaltrusaitis/OpenFace)、[L2CS-Net](https://github.com/Ahmednull/L2CS-Net)、[MobileGaze](https://github.com/yakhyo/gaze-estimation)

## 4. 实际模型与流程

```text
视频文件 → 解码并每秒采 5 帧
    → MediaPipe：人脸数、478 个关键点、头姿变换
    → MobileGaze MobileOne-S0：人脸图像 → yaw/pitch 目光估计
    → 质量检查：人脸数、眼睛大小/开放度、图像质量
    → 自行训练的头部/眼动分类器
    → 连续事件合并（演示值：至少 2 秒）
    → measurements.jsonl + timeline.json
```

- **头部模型：** 3 个旋转分量及其绝对值 → 标准化 → Logistic Regression。仅使用旋转正负值的线性模型失败，因为左右/上下偏转位于中心的两侧；加入绝对值表达了“偏离中心”的几何关系。
- **目光模型：** 冻结 MobileGaze，使用其 yaw/pitch、绝对值及 MediaPipe 眼部/头部特征 → 自行训练的平衡 HGB 分类器。对正向头姿训练的眼动模型，只在头部模型判断正向且眼部质量合格时输出事件。
- **未重新训练人脸或目光 CNN。** 本轮训练的是特征上的分类器；小数据下从零训练视觉编码器不合适。
- **没有屏幕坐标校准。** 能得到相对摄像机的方向和数据集方向分数；无法据此确定候选人正在看哪个窗口。
- **多人/人脸缺失：** 直接记录检测状态；多人时不选定其中一人继续解释眼动；人脸检测丢失可能来自离开、遮挡、极端转头或检测失败。
- **时间对齐接口：** 输出秒级起止时间，后续可以与 ASR 的 answer window、transcript signal 对齐。本轮没有同步的 AI-use 标签，因此没有训练视频＋文本融合权重。

每帧方向分数与 `ai_assistance_probability` 分开，后者当前为 `null`。这使后续团队能使用可解释事件，而不把方向分类概率误作作弊概率。

## 5. 实验与结果如何解读

### 5.1 三人方向数据：先验证组件

选帧在模型运行前固定，11 段序列各均匀选 70 帧；文件名的 S1/S2/S3 用于按人拆分。770 个源图哈希互异。YOLO 0–4 为头部区域、5–9 为眼部区域；中心类别 3/8 依据标注与可视检查解释。发布包未包含类别名称文件，因此保留原 ID 和这项映射来源。两个眼部标注不一致或不全时不建立目光标签。

质量结果：504 帧眼部合格、153 帧眼部低质量、113 帧未检测到脸。后者全部落在原标注的左右大幅转头类别，说明**“没检测到脸”不能自动叫作“人离开了”**。

头部任务可用 657/770 帧；眼动任务要求标注与质量有效，可用 451 帧；再限制头正向后为 154 帧。普通关键点 HGB 的整体眼动 AUC 0.8193，但限制头正向后降至 0.4781。专用 MobileGaze/LR 把同一 154 帧上的 AUC 提升至 0.7786。后一个比较更接近我们关注的细微眼动问题。

### 5.2 Columbia：扩大到 56 人

固定选所有参与者的 0° 头姿，保留全部 21 个目光目标，不按模型表现挑样本。1,176 图全部通过本轮质量门槛。定义：水平或垂直目标偏移达到 10° 为正类；垂直为 0°、水平 -5°/0°/+5° 为中心类。该定义是目光方向任务定义，不代表获准/违规看屏幕的边界。

正类 1,008、负类 168。5 折按参与者划分，任一测试参与者的所有图像都不进入该折训练。模型采用固定参数，目光网络保持冻结。

| Columbia 变体 | AUROC | 阈值 0.5 下 FPR | 召回 |
|---|---:|---:|---:|
| 关键点 + LR | 0.5316 | 51.8% | 55.4% |
| MobileGaze + LR | 0.7967 | 26.8% | 68.8% |
| 组合特征 + LR | 0.7987 | 26.8% | 69.6% |
| 组合特征 + 默认 HGB | 0.8466 | 82.1% | 96.5% |

最后一行排序不错，但阈值非常不适用。正类比例较高，导致较高的 F1 仍可能伴随大量中心目光误报。因此主要看 AUROC、FPR、召回和平衡准确率，不能仅看 F1 或总体正确率。

### 5.3 改进：类别平衡与嵌套阈值

HGB 加入训练类别权重。每个外层训练折内部再做 3 折参与者拆分，用内部未见过的中心类分数选择名义 10% FPR 的阈值。然后在外层全新参与者上评价。**外层测试标签不参与阈值选择。**

最终固定 OOF 预测汇总：

- AUROC **0.8414**；按参与者 bootstrap 的 95% 区间 **0.8107–0.8685**。
- FPR **13/168 = 7.74%**；相应区间 **3.57%–12.50%**。
- 召回 **606/1,008 = 60.12%**；相应区间 **56.25%–63.79%**。
- 平衡准确率 **76.19%**。
- 单折 FPR 从 0% 到 24.2%，说明人群/设备迁移仍需检查。

区间来自 1,000 次按人重采样固定 OOF 预测，没有在每次 bootstrap 中重新训练整个模型。本轮经历过探索与模型比较，不能把这些区间或该最佳候选当成一次全新、未触碰的最终检验。

打乱标签的 MobileGaze/LR 对照 AUC **0.5030**，接近随机。三人数据训练的模型不做 Columbia 拟合、直接迁移的 AUC **0.7542**；这说明存在方向信号，也存在数据分布差异。

## 6. 完整视频流程实测

使用 OpenFace 作者仓库公开示例，仅作为工程流程检查；这些片段没有本轮 AI-use 标签，也没有用于上述方向模型训练。

| 检查 | 实测输出 |
|---|---|
| `default.wmv` | 19.2 秒，5 fps，96 次采样；模型加载后的处理阶段 3.02 秒；未形成 ≥2 秒事件 |
| `multi_face.avi` | 23.4 秒，117 次采样；输出多人事件 0–5.6 秒与 7.8–11.0 秒 |
| 生成的全黑 3 秒片段 | 15 次采样，准确输出 0–3 秒 `no_face_detected` 事件；属于机械检查，不是现实人脸丢失准确率 |

在本机 Apple M4 上，最终单人示例每采样帧推理中位数约 **29.6 ms**，P95 **31.5 ms**；多人示例 P95 约 34.3 ms。5 fps 每帧有 200 ms 预算，当前计算速度足够做这一采样率的原型。Google Meet/Chrome 实时采集、传输、拥塞与浏览器集成尚未测试。演示事件至少需积累 2 秒，不能把单帧推理耗时当成完整告警延迟。

## 7. 下一步，按收益排序

1. **收到 MIT 视频后直接跑迁移检查。** 检查是否存在切镜头、多人/面试官画面、脸部像素不足、眼镜反光；标注一小批真实转头/眼动/失踪片段，评估事件级误报。MIT 评分保留原意，不能转换成作弊标签。
2. **优先解决 DeepVerify 访问。** 其脚本场景比更多人格数据更贴题；先核对订阅权限与下载后的真实目录/标签，不假设 303 段都属于行为子集，也不把遮挡等同于 AI 辅助。
3. **采集受控的、已知辅助条件的视频。** 第一轮建议 12–20 人用于可行性，不宣称总体准确率；之后扩展到至少 30 人并保留全新参与者做独立测试。条件至少包括独立回答、看自己写的笔记、逐字读 AI 答案。加入自然思考看别处、屏幕上看面试官、眼镜/灯光变化作为困难负例。问题与顺序需要平衡，避免重复同题学习效应。
4. **录制时做方向基线。** 在知情同意下录短校准片段：看摄像头、看面试官区域、看屏幕左右位置。比较相对个人基线的偏移，而非要求所有人盯摄像头。校准方案需要另行独立验证。
5. **事件级评估先于增加大模型。** 用真实视频时间戳标注目光方向、转头、遮挡等事件；报告每分钟误报、事件召回、持续时间误差、P95 延迟、不可测覆盖率。图片任务的 FPR 不是每分钟误报率。
6. **再与现有 ASR/text 做时间对齐。** 在回答窗口内组合持续目光事件与文本信号，再训练小型融合模型。先比较 transcript-only、video-only、二者组合；只有同一批、有真实辅助条件的数据才支持这种比较。若动作相同，仅凭视频无法区分人类笔记与 AI 笔记，应允许低证据输出。

原有 3 个事件/标注单元测试通过，并用合成 ZIP 验证了提取、复用校验和文件不一致时拒绝复用。

MIT 原视频到齐后的顺序是：验证 ZIP → 核对画面布局 → 固定 3 人的前/后两场各 60 秒试跑
→ 检查可测率与事件样本 → 根据画面质量扩大处理。暂不使用其表现评分训练作弊分类器。

## 10. MIT 全量视频实验与校准比较（已完成）

已取得独立的 Videos.zip（7,510,773,677 字节），校验并处理 **138 段 / 69 人**全部视频。
本地解码总计 **13.32 小时**，640×480、29 fps；全量按 **2 fps** 采样，得到 **95,945** 次测量，
两路本地 CPU 进程约 50.2 分钟完成，零处理错误。解码时长与源元数据的最大差异为 0.138 秒。

固定的小批试验为前三个实际存在的参与者（P1/PP1、P3/PP3、P4/PP4）各前 60 秒，5 fps。
1,695 个可测头部帧全部触发原绝对朝向模型，目光分支因头部条件被全部关闭。
这说明正面朝向规则不能直接迁移到斜拍面试。

随后测试第一段 30 秒的自然朝向参考，排除参考时间后统计：

| 指标 | 全量结果 |
|---|---|
| 后续统计范围 | 12.17 小时、87,665 次采样 |
| 头部 / 目光参考可建立 | 138/138、123/138 段 |
| 头部可测覆盖率 | 97.61% |
| 目光可测覆盖率，原规则 → 相对参考 | 2.34% → 54.05% |
| 持续朝向变化事件 | 头部 769、目光 797；另有未检测到脸 51、多人脸检测 5 |
| 单次测量耗时中位数 / P95 | 54.2 / 77.7 ms；两路并发环境 |

**上述事件数和覆盖率不是准确率。** 六组定性抽查中，发现开头低头写材料会污染参考朝向，
使随后正常抬头回答形成长事件；另有站起、空椅子等非回答时段。部分未检测到脸和多人脸事件也存在检测器错误。
因此，先识别有效面试/回答区间，并在候选人准备好后明确校准，是下一步必要工作。
不能把文件开头 30 秒直接作为产品中的“正常回答”标准。

在有真实方向标签的 Columbia 数据上，逐人使用一张已知正中视线图片作参考，并排除该图，
剩下 56 人、1,120 图用于评分（1,008 偏移、112 接近正中）：

| 冻结模型 | 未校准 AUC | 单点校准 AUC | 按人 bootstrap 95% 区间 |
|---|---:|---:|---|
| MobileOne-S0 | 0.7841 | **0.8824** | 0.8467–0.9126 |
| ResNet-34 | 0.7409 | 0.8422 | 0.7971–0.8848 |

同一批图上 S0−ResNet 的 AUC 差为 0.0401，配对按人重采样区间 0.0030–0.0762。
本轮保留较轻的 S0。五点已知目标校准另测了 896 张保留图，S0 AUC 0.9016；同组单点为 0.8847，
差值区间 −0.0068–0.0417，尚不能确认增加校准点有稳定收益。MIT 没有这些已知目标，未套用五点方案。
这些均为探索性的**方向指标**，并非 AI 辅助面试检测指标。
